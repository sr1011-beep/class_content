1. String class - 자바에서 문자열 처리
(1) 암묵적인 객체 생성 지원
    ex : 기존 방법(원칙적인 방법)
        String str = new String("ABC");

        간단하게 쓸 수 있도록 지원
        String Str = "ABC"; // 실제로 내부적으로는 new String("ABC") 동작

    * 주의
        String str1 = "ABC";
        String str2 = "ABC";
        => 꼭 기본 자료형 처럼 str1에 "ABC"라는 값이 들어가 있는것 처럼 착각
        실제로 str1 에는 주소값이 들어가 있음
        따라서 String 객체값 비교를 할 때
        if (str1 == str2) => 잘못된 코드 : 값비교가 아니라 주소값 비교
        if (str1.equals( str2 ) => String 객체 값비교를 하고 싶으면 꼭!! 이렇게 사용)

(2) 불변적인 특징을 가짐
    String str = "ABC"; // 메모리에 "ABC"값을 가지는 위치 str에 저장
    str = str + "D";    //"ABC" 수정이 불가능 하므로 "ABCD" 메모리에 새로   만들고 그 주소를 str에 저장
    str = str + "E";    //"ABCD" 수정이 불가능 하므로 "ABCDE" 메모리에 새로 만들고 그 주소를 str에 저장

    String 객체는 한번 값 할당을 하면 변경이 불가능
    따라서 위의 코드는 결론적으로 메모리에 "ABC" "ABCD" "ACBDE" 와 같은 3개의 객체가 만들어지게 됨

    결론적으로 추후 서비스 구현에 있어 지속적으로 변경이 되는 문자열 값을 저장하기 위해서는 String 클래스를 사용하면 안됨!! 불필요하게 메모리를 낭비하게 되는 문제로 인해 메모리릭이 발생
    빈번하게 자주 변경되는 문자열 저장 관리를 위해서는 대안으로 StringBuffer class 등을 사용해야 함

2. 생성자내 중복되는 코드 제거
- 생성자의 문법 특징
 : 메소드와 유사하나 리턴형이 없고 생성자 이름이 클래스명과 같아야함
 - 생성자는 메소드처럼 호출이 가능한데 프로그래머인 저희가 재활용을 필요로 할때 호출하는게 아니라 클래스가 객체화 될때 단한번 호출
    -> 클래스가 객체화 될 때 호출
        new test(); -> 생성자 호출
- 생성자를 사용하는 가장 큰 목적은 멤버변수 초기화
- 생성자 오버로딩 가능
    -> 하나의 클래스에 동일이름의 생성자 여러개를 정의해줄 수 있음
    -> 이름이 같은 생성자가 여려개이므로 구분을 위해 파라미터 종류가 개수라 달라야 함

- 자 그럼 멤버변수 초기화라는 목적상 생성자 오버로딩 하다보면 필연적으로 중복되는 코드가 발생할 수 밖에 없고 이를 해결하기 위해 자바에서 제공하는 문법은?
    this()

3. this()   , this
 - 지금은 편안하게 클래스내에 this가 보이면 현재클래스를 가리킨다고 보면됨
 - this() : 현재 클래스 생성자 호출
